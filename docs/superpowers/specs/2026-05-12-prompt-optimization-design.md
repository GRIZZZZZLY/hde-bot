# Prompt Optimization via Claude Code — Design Spec

**Date:** 2026-05-12  
**Status:** Approved  
**Scope:** Improve AI hint quality (Суть/Клиенту/Памятка) using offline analysis with Claude Code. No Claude API key required. Gemini/Groq remain as runtime LLMs.

---

## Problem

Three observed quality issues with current AI hints:

1. **Суть расплывчатая** — describes symptom, not technical cause
2. **Памятка общая** — lacks concrete steps, commands, file paths
3. **Нет структуры мышления** — model generates answer directly without reasoning chain, misses context

---

## Approach

**Offline prompt engineering loop:**

```
VPS SQLite → rsync → local copy
→ export_for_analysis.py → JSON files
→ Claude Code reads + analyzes patterns
→ rewrites ai_summary.py system prompt
→ git push → VPS pulls + restarts
```

No changes to: RAG pipeline, embeddings, database schema, Telegram handlers.

---

## Components

### 1. DB Sync (`tools/sync_db.sh`)

One-directional: VPS → local. Run manually before each analysis session.

```bash
#!/bin/bash
# Usage: ./tools/sync_db.sh user@vps:/path/to/hde_bot.db
rsync -avz "$1" ./hde_bot_local.db
echo "Synced: $(du -sh ./hde_bot_local.db)"
```

### 2. Export Script (`tools/export_for_analysis.py`)

Reads `hde_bot_local.db`, writes three JSON files to `tools/analysis/`:

| File | Source table | Content |
|------|-------------|---------|
| `knowledge_items.json` | `knowledge_items` | id, title, content, quality, company_name, source |
| `feedback_samples.json` | `optimization_samples` | ai_suggestion, operator_reply, outcome, ticket_id |
| `stats.json` | aggregated | quality distribution, outcome counts, top companies |

**`outcome` values in optimization_samples:** `accepted`, `rejected`, `corrected`, `sent`

### 3. Prompt Rewrite (`bot/ai_summary.py`)

Target: the system prompt passed to Gemini in `generate_ticket_summary()`.

**Changes:**

**Суть:** Add constraint — "8–12 слов, только техническая причина (не симптом). Неверно: 'клиент не может войти'. Верно: 'LDAP-аутентификация отклоняет токен из-за истёкшего сертификата'."

**Памятка:** Add constraint — "минимум 3 конкретных шага. Если применимо — команды, пути к файлам, настройки. Не писать общие советы."

**Chain-of-thought:** Add hidden `<reasoning>` block before answer sections. Gemini fills it (not shown to user) to reason through the problem before generating output. Strip `<reasoning>...</reasoning>` from final output before display.

**Few-shot examples:** Inject 5 `accepted` samples from `feedback_samples.json` into system prompt as labeled examples. Selection: most recent 5 with outcome=`accepted`, one per unique company where possible (for diversity). Refresh by re-running export script + restarting service.

### 4. Few-shot Injection Architecture

Few-shot examples live in `bot/prompts/few_shot_examples.json` (auto-generated by export script). `ai_summary.py` reads this file at module load time and injects into system prompt string.

This separates prompt structure (code) from training examples (data), making future updates easy without touching Python.

### 5. Deploy

```
git push origin main
ssh user@vps "cd /path/to/hde_bot && git pull && systemctl restart hde_bot"
```

Only `ai_summary.py` and `bot/prompts/few_shot_examples.json` change on VPS.

## Out of Scope

- RAG pipeline changes (RRF weights, embedding model)
- Claude API integration (no key)
- Database schema changes
- Photo analysis pipeline changes
- Automatic sync / cron jobs

---

## Success Criteria

1. `sync_db.sh` downloads DB from VPS in <30s
2. `export_for_analysis.py` produces valid JSON from local DB
3. System prompt includes chain-of-thought block, Суть/Памятка constraints, and ≥3 few-shot examples
4. All 178 existing tests pass after `ai_summary.py` change
5. Subjective: Суть becomes more specific, Памятка includes actionable steps
