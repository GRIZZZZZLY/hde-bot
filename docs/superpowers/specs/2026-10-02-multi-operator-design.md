# Один бот на трёх инженеров оборудования

Дата: 2026-10-02. Статус: выбран владельцем («один бот на троих»); этап 0 выложен; план поправлен по разбору рисков 2026-10-02.

## 1. Цель

Бот, который сейчас работает только на Игоря, обслуживает трёх инженеров:

| Инженер | HDE id | Telegram id | Группа |
|---|---|---|---|
| Игорь Кравцов | 98 | 555502880 | текущая `GROUP_CHAT_ID` |
| Максим Яницкий | 102 | 1220214456 | своя супергруппа, бот там админ (id группы ещё не известен) |
| Юрий Коржов | 61 | — | нет |

Каждый получает в своей группе топики по своим тикетам, General с кнопками
«Беру сейчас / N ч» по неприсвоенным тикетам «Оборудования» и отвечает клиенту
из Telegram от своей учётки HDE (свой API-ключ).

**Критерий успеха:** тикет, назначенный на 102, появляется топиком в группе
Максима; `/send` Максима в этом топике виден в HDE от имени Максима; у Игоря
ничего не меняется.

**Вне первой версии:** ИИ-черновики, саммари, дайджесты и ночные сверки для
коллег (общий ключ Groq, 200 тыс. токенов в сутки). Включаются флагом на
инженера позже.

## 2. Решения

- **Реестр инженеров.** `Operator(hde_id, name, first_name, tg_user_id, chat_id,
  personal_chat_id, api_email, api_key, ai_enabled)`. Первый инженер
  собирается из текущих переменных `.env` (`HDE_OWNER_ID`, `GROUP_CHAT_ID`,
  `PERSONAL_CHAT_ID`, `HDE_API_EMAIL`, `HDE_API_KEY`), поэтому для Игоря ничего
  не меняется. Остальные читаются из файла `OPERATORS_FILE` (JSON, права 600):
  там их ключи, в `.env` их нет.
- **Чей тикет.** Ищем инженера по `owner_id` из вебхука. Имя только
  запасной вариант: в вебхуках бывает «Максим» вместо «Максим Яницкий».
- **Где топик.** В `ticket_topics` появляется `chat_id`. Все отправки в топик
  берут чат из записи, а не из `config.group_chat_id`. Существующие ~1900
  записей получают текущую группу Игоря.
- **Топик ищется по паре (чат, номер топика).** Номер топика уникален только
  внутри группы. У Игоря номера 300–38 499, у новой группы они начнутся с 2, и
  через пару сотен тикетов пересекутся с закрытыми записями Игоря. Таблицы,
  где ключ — только номер топика (`reply_drafts`, `topic_media_cache`,
  `sent_hde_messages`, `ai_feedback_pending`, `ai_suggestions`), получают
  `chat_id` в ключ. В SQLite это пересборка таблицы, до неё делается бэкап.
- **Чей ключ HDE.** Действие из Telegram (кнопка, `/send`, `/note`, правка,
  удаление, автозаполнение) идёт ключом того, кто нажал. Игорь в группе Максима
  может делать всё, и его ответ подпишется Игорем: это честно. Фоновые задачи
  (успокаивающее сообщение по SLA) идут ключом исполнителя тикета. Чтение
  тикетов остаётся на общем ключе.
- **Передача тикета X → Y.** Топик у X закрывается, как сейчас при снятии
  исполнителя. У Y открывается новый топик с историей. Сейчас бот в этом случае
  только закрывает топик.
- **General.** Уведомление о неприсвоенном тикете уходит в General каждой
  группы. Кто первый нажал кнопку, на того и назначается тикет, а в остальных
  группах уведомление меняется на «Забрал X». В `unassigned_general_messages`
  ключ становится (тикет, чат).
- **Чужие чаты.** Бот отвечает только в группах и личках инженеров из
  реестра. Сейчас такой проверки нет, а бот Игоря уже стоит в группе Максима.
- **Правила HDE.** Правила №55, 56, 57, 59, 60 шлют события боту только при
  исполнителе 98 (или для департамента 3 «Оборудование»). В них надо добавить
  102 и 61 через ИЛИ. Это делается через веб-админку HDE с обязательным
  перечитыванием `rule_form` (ловушка с `activity`). Правило №45 Максима
  (уведомления напрямую в Telegram) выключается, когда Максим это подтвердит.
- **Лимиты.** HDE: 300 запросов в минуту на весь аккаунт, общий ограничитель
  бота (`HDE_API_MAX_RPM=80`) остаётся одним на все ключи. Обновление топиков
  (`refresh`) обходит инженеров по очереди.

## 3. Этапы

Каждый этап выкладывается отдельно и для Игоря ничего не меняет, пока не
подключён второй инженер.

| # | Этап | Проверка |
|---|---|---|
| 0 | Фильтр чатов: только группы и лички инженеров | тест: апдейт из чужого чата не доходит до обработчиков |
| 1 | Реестр инженеров; `matches_owner` → «какой инженер»; `is_operator_allowed` по реестру | все тесты зелёные, поведение не меняется |
| 2 | Схема БД: `chat_id` в `ticket_topics` и в ключи пяти таблиц, перенос данных | бэкап; число строк до и после совпадает |
| 3 | Все отправки в топик берут чат из записи (41 место) | тест: тикет с `chat_id`=B уходит в B |
| 4 | `HDEApiClient(operator)`; запись в HDE идёт ключом нажавшего | тест: `/send` от второго инженера идёт его ключом |
| 5 | Маршрутизация по инженеру, передача X → Y, General в каждой группе, `refresh` по инженерам; захват тикета в БД до `assign_ticket` (гонка «Беру») | тесты на передачу и на «первый нажал» |
| 5a | ИИ только при `operator.ai_enabled`: автоподсказка, Vision по фото, саммари истории, расшифровка, ночные сверки | тест: тикет инженера без ИИ не вызывает ни одной LLM |
| 6 | Подключить Максима: запись в `OPERATORS_FILE`, его ключ, правила HDE. Правило №45 НЕ выключать 2 недели | его тикет появляется в его группе; ответ в HDE от его имени; ежедневно: открытые тикеты 102 в HDE = активные топики в его группе |
| 7 | Юрий: то же, что этап 6 | то же |

## 4. Обязательные защиты (из разбора рисков)

- **Стоп на границе записи.** `/send`, `/note`, правка, удаление, кнопки
  отказывают, если `record.chat_id` не равен чату, откуда пришла команда.
  Ответ не тому клиенту — самая тяжёлая ошибка, и её не отменить.
- **Тест-сторож.** Падает, если `config.group_chat_id` встречается вне
  `config.py` и реестра инженеров. Мест больше, чем 41: ещё 11 вызовов
  закрытия, правки и удаления топиков, `refresh.py` шаг 4
  (`delete_forum_topic`), `_awaiting_correction`.
- **Тесты с пересекающимися номерами.** В тестах этапов 2–5 у двух групп
  одинаковые номера топиков: на чистой базе совпадений нет, и ошибка не видна.
  Номера пересекутся в первые дни, а не через сотни тикетов: у Игоря ~20
  номеров на тикет, группа Максима дойдёт до 300 примерно за 15 тикетов.
- **Проверка ключа до этапа 4.** Один внутренний комментарий ключом Максима
  на тестовом тикете, автор в HDE должен быть «Максим Яницкий». Ключ передаёт
  сам Максим. Если проверка провалилась — стоп.
- **Откат.** Убрать инженера из `OPERATORS_FILE` и перезапустить: бот снова
  работает только на Игоря.
- **Когда остановиться.** Сообщение ушло не в тот тикет или не в ту группу →
  сразу откат. К 16.10 у Максима меньше 3 `/send` в рабочий день → Юрия не
  подключать, спросить Максима, что мешает.

## 5. Что нужно от владельца

- Номер группы Максима: бот запишет его в журнал, когда Максим напишет что-нибудь в группе.
- API-ключи HDE Максима и Юрия: передают сами коллеги (бот будет писать клиентам от их имени), записываются на сервер командой, не через чат.
- Telegram id Юрия и его группа.
- Согласие на правку правил HDE №55–60; правило №45 выключается не раньше чем через 2 недели без пропусков.
