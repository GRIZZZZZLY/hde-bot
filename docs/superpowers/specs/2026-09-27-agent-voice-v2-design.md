# Агент черновиков v2: регламент «Лояльная техподдержка», короткий промпт, черновик на каждое сообщение

Дата: 2026-09-27. Статус: на ревью владельца.
Основание: разбор `docs/agent-review-2026-09-27.md` (данные прода, слабые места,
SkillOpt, аналоги).

## 1. Цель и критерии успеха

**Цель.** Черновик ответа клиенту, который владелец отправляет в HDE почти без
правок. Черновик по сути верен, а по форме соответствует регламенту
`docs/Лояльная техническая поддержка — anti-slop.md`. Регламент обязателен и при
конфликте побеждает любые другие стайлгайды.

**Ограничения:**
- Groq, модель `qwen/qwen3.8-27b`: 8000 токенов в минуту (TPM), 1000 запросов в
  день. Лимит проверен по заголовкам ответа 2026-09-27;
- кэширование промпта для qwen недоступно;
- бот ничего не отправляет клиенту без кнопки оператора.

**Критерии успеха.** Проверяются на замороженном наборе из 50 тикетов (раздел 7),
новый путь против старого:

| Что | Порог |
|---|---|
| Удалёнка в черновиках | ≤ 20% (сейчас 49%, у операторов 14%) |
| «Ждите инженера / звонка / специалиста» | ≤ 20% (сейчас 36%, у операторов 4%) |
| Серьёзные пометки проверок кодом (раздел 5) | 0 |
| Чек-лист регламента (раздел 7.2) | ≥ 80% черновиков проходят все применимые пункты |
| Суть: «то же действие, что у оператора» или «бот лучше» | не ниже, чем у старого пути |
| Слепое A/B на 20 эталонах по регламенту | новый путь выигрывает |
| Проверка владельцем 10 пар | «да» |

## 2. Решения, принятые на обсуждении

| Вопрос | Решение |
|---|---|
| Какой черновик нужен | Готовый ответ, который отправляют почти без правок |
| Когда приходит | Автоматически на первое сообщение тикета и на каждый новый ответ клиента. На ответах клиента черновик дописывается в то же сообщение. Включается только после проверки качества |
| Подход | Один вызов модели, промпт собран заново и укладывается в ~6 тыс. токенов. Решение «ответить / спросить / опоры нет» принимается внутри того же вызова (поле `analysis`). Переход на два вызова — только если проверка покажет, что уточняющие вопросы остались слабыми |
| Эталон для проверки | Ответы операторов написаны до регламента. Их используем только как эталон **сути** (какое действие), а не **формы**. Форму проверяем только по чек-листу регламента. Плюс 20 эталонов по регламенту: суть от оператора, форма по регламенту; пишет ассистент, правит владелец |

## 3. Путь черновика

```
событие (новый тикет / ответ клиента / кнопка 🔄)
  → сбор контекста (4.1)
  → один вызов qwen (4.2), JSON
  → проверки кодом (5): мелочи правятся, серьёзное → пометка в Памятке
  → доставка в Telegram (6)
  → запись в ai_suggestions (+ analysis, + результат проверок)
```

Изменения по шагам:

1. **Триггеры:**
   - первое сообщение нового тикета — существующий флаг
     `AI_SUGGESTION_AUTO_ENABLED`;
   - `client_reply` — новый флаг `AGENT_REPLY_DRAFTS_ENABLED`, по умолчанию
     выключен;
   - кнопка 🔄 (бывшая 💡) работает всегда, в том числе на сообщении нового
     тикета.
2. **Контекст:**
   - история без макросов первой линии и бота (переиспользуем `BOILERPLATE_RE`
     и `MACRO_RE` из `agent/operator_text.py`);
   - запрос к поиску: тема + первое содержательное сообщение клиента + последнее
     содержательное. Содержательным не считаются телефоны, id и подтверждения:
     переиспользуем `operator_text.is_meaningless` плюс отсев строк из одних
     цифр;
   - база знаний: 1–2 самых похожих куска статьи через `knowledge/chunker.py`
     вместо первых 600 символов записи;
   - 2 похожих прошлых ответа из `dialogue_pairs`, сначала ответы владельца,
     без приветствий и подписей. Используются только как источник конкретики;
   - пометки кодом: `stress` (регулярка, раздел 4.3) и `first_staff_reply`.
3. **Один вызов** `qwen/qwen3.8-27b`, `max_tokens=600`, `temperature=0.3`,
   `reasoning_effort=none`.
4. **Self-check выключен** на новом пути. Вместо него — проверки кодом.
5. **Ошибка провайдера (429/413).** Один повтор после
   `x-ratelimit-reset-tokens`. Старый запасной путь `generate_ticket_summary` на
   новом пути не вызывается ни для авто-черновиков, ни для кнопки. Не получилось
   — черновика нет, кнопка 🔄 остаётся, в лог пишется предупреждение.
6. **Всё новое** работает только при `AGENT_VOICE_V2_ENABLED=true`. При false
   поведение прежнее.

## 4. Промпт

### 4.1. Состав и бюджет

Порядок: постоянное → данные тикета → формат. Оценка «1 токен ≈ 2,1 символа»
снята по логу прода: запрос 11 699 токенов при промпте около 24 тыс. символов.

| # | Блок | Откуда | Символов |
|---|---|---|---|
| 1 | Роль | константа в `agent/voice.py` | ~300 |
| 2 | Голос по регламенту | `bot/prompts/voice_ru.md` | ~1800 |
| 3 | Выбор действия | константа | ~800 |
| 4 | Суть и Памятка (выжимка v15) | константа | ~800 |
| 5 | Эталонные примеры (6 шт.) | `bot/prompts/voice_examples.json` | ~1500 |
| 6 | Данные тикета: факты, куски статей с id, 2 прошлых ответа, пометки | собирается | ≤2500 |
| 7 | Формат JSON | константа | ~500 |
| — | История (сообщение пользователя) | `build_history_budgeted` | ≤3000 |

Итого ≤ ~11 200 символов, это ≈ 5,3 тыс. токенов плюс 600 на ответ, около
5,9 тыс. токенов на запрос.

Тест `test_voice_prompt_budget` собирает промпт по худшему случаю (все блоки на
максимуме) и падает, если суммарный объём больше 11 500 символов.

**Роль (блок 1).** Помощник инженера 2-й линии: кассы, Posiflora, эквайринг.
Фразу «базовую диагностику уже провели» убираем. Вместо неё: «быстрый шаг,
который клиент сделает сам, лучше удалёнки».

**Выбор действия (блок 3):**
- ANSWER — есть шаг из источников или истории;
- ASK — не хватает данных, ровно один вопрос, с объяснением зачем;
- ESCALATE — деньги, фискальные изменения, необратимые действия, доступы;
- NO_ACTION — клиент не задал вопроса;
- если опоры нет ни в источниках, ни в истории — ASK, шаг не выдумывать;
- удалёнку предлагать, только если шага нет. Ссылки: AnyDesk
  https://anydesk.com/ru, RuDesktop https://rudesktop.ru/downloads/.

**Формат (блок 7):**

```json
{"analysis": "что сломано, что уже пробовали, хватает ли данных",
 "action": "ANSWER|ASK|ESCALATE|NO_ACTION",
 "suit": "диагноз 8–18 слов",
 "client": "текст клиенту по голосу; пусто для NO_ACTION/ESCALATE",
 "memo": "пункты через «•» или «—»",
 "source_ids": ["KB#123", "pair#456"],
 "confidence": 0}
```

### 4.2. Голос (`bot/prompts/voice_ru.md`)

Единственный источник правил для поля `client`. Его же читает судья (раздел 7)
вместо `bot/prompts/style_guide_ru.md`. Черновик текста — приложение А разбора.
Правила, которые снимают противоречия нынешнего промпта:

- ответ: 1–2 предложения, третье — только для предупреждения о риске или
  «зачем»; потолок около 50 слов;
- порядок частей: признание (только при `stress`) → риск → шаг или один вопрос
  (с «зачем» при просьбе данных) → просьба проверить результат (после
  инструкции);
- «пришлите номер — я подключусь» можно; прошедшее время о несделанном нельзя;
  обещания за других и сроки, которых нет в истории, нельзя;
- «номер рабочего места» (так поле называется в русском AnyDesk), «пожалуйста»
  один раз можно;
- «Добрый день» — только при `first_staff_reply`.

### 4.3. Пометка `stress`

Регулярка по сообщениям клиента в истории. Около 15 маркеров:

- повтор: опять, снова, вчера уже, до сих пор, который раз;
- простой: очередь, закрыть смену, не можем продавать/пробить, клиенты ждут,
  стоим, срочно;
- раздражение: «!!», где ваш, сколько можно;
- ожидание: жду уже, никто не отвечает.

На базе прода маркеры есть в 13% тикетов. В промпт идёт строка `Сигнал: стресс`
или ничего.

### 4.4. Эталонные примеры (`bot/prompts/voice_examples.json`)

Шесть пар «ситуация → ответ по регламенту» на реальных тикетах: #953, #1090,
#1116, #881 и два с ASK. Суть взята у оператора, форма — по регламенту.
Пишет ассистент, утверждает владелец. Из агентного пути уходят:
`few_shot_examples.json`, `voice_profile.json`, примеры внутри v15.

### 4.5. Что уходит из агентного пути при v2

- `get_active_format_instructions()` (v15 из БД);
- `build_action_instruction()`;
- `build_json_override()`;
- `_build_system_prompt()`.

Сами они остаются в коде и в БД: ими пользуются старый путь (флаг выключен) и
откат.

## 5. Проверки кодом (`bot/agent/lint.py`)

Чистые функции, без вызовов модели.

| Правило | Уровень | Действие |
|---|---|---|
| Пароль в Памятке (токен после «пароль», «password», «pwd») | fix | заменить на «•••» |
| Приветствие не при `first_staff_reply`; дежурная концовка (`CLOSER_RE`) | fix | вырезать |
| Обещание за других: (инженер/специалист/разработчик/мастер/техник) + (свяж/позвон/перезвон/подключ/приед/провер/ответ) — если этого слова нет в staff-репликах истории | hard | пометка |
| Срок: завтра, в понедельник…, «с N утра/часов», «в течение N» — если нет в истории | hard | пометка |
| Якорь: телефон, число от 4 цифр, URL, версия в `client`, которых нет в истории, источниках, фактах тикета или в белом списке ссылок из блока 3 | hard | пометка |
| Прошедшее время о своих действиях: подключил(ся), настроил, проверил, обновил, исправил, перезагрузил | hard | пометка |
| `source_ids` вне списка найденных | hard | пометка |
| Конвейерные фразы (список из регламента и v15), больше одного «?», больше 60 слов | soft | только запись |

- Пометка — одна строка в Памятке: `⚠️ Проверь: <первое hard-нарушение>`.
- Результат пишется в `ai_suggestions.self_check` как
  `{"lint": {"fixed": [...], "hard": [...], "soft": [...]}}`, без изменения схемы
  базы.
- Автоисправление моделью в эту работу не входит. Решение о нём — по статистике
  `hard` после двух недель работы.

## 6. Доставка в Telegram

- Одно сообщение вместо трёх (Суть / Клиенту / Памятка).
- **Ответ клиента.** После генерации сообщение с ответом клиента редактируется:
  к его тексту дописываются разделитель, `💡 <code>текст клиенту</code>`,
  `📝 Памятка` и, если есть, `⚠️ Проверь: …`. Клавиатура: `📤 Ответить клиенту`
  (`ai:send_post`, уже есть), `✏️ Исправить` (`ai:edit`, уже есть),
  `🔄 Другой вариант` (`ai:suggest`).
- Правка сообщения идёт без уведомления. Лимит сообщения 4096 символов: если не
  помещается, текст клиента в исходном сообщении обрезается до 1500 символов со
  ссылкой на HDE.
- **Новый тикет.** Одно сообщение без звука после карточки клиента: Суть,
  черновик, Памятка, та же клавиатура.
- **NO_ACTION.** В сообщение ничего не дописывается, остаётся кнопка 🔄.
- **ESCALATE.** Дописывается только строка Памятки с причиной.
- **Устаревание.** При новом ответе клиента у прошлого сообщения убирается
  клавиатура (`_strip_prev_suggest_button`, уже есть).
- Кнопки 👍/👎 на новом пути не показываются.
- `<code>` выбран потому, что в Telegram такой текст копируется нажатием.
  Экранирование HTML — через `html.escape`.

## 7. Проверка качества и включение

### 7.1. Замороженный набор

- 50 последних `ai_suggestions` с `judge_reference_answer`: разные тикеты, не
  больше 10 NO_ACTION и ESCALATE.
- Для каждого: `history` (как видел бот), `client_text`, `title`, эталон сути —
  ответ оператора.
- 20 из 50 дополнительно получают эталон по регламенту:
  `data/golden/regulation_gold.json`, пишет ассистент, правит владелец.
- Файл набора: `data/golden/voice_v2_set.json`, создаётся скриптом из прод-БД
  (только чтение).

### 7.2. Прогон и оценка

Скрипт `scripts/eval_voice.py`, запускается на сервере ночью.

1. Для каждого кейса генерирует старым путём (`AGENT_VOICE_V2_ENABLED=false`) и
   новым. Это около 100 запросов, пауза между ними под TPM.
2. Считает кодом:
   - удалёнку;
   - «ждите инженера»;
   - hard и soft проверок (раздел 5);
   - число «?»;
   - длину;
   - есть ли просьба проверить результат.
3. Выгружает JSON для слепого A/B: пары в случайном порядке, без меток пути.
4. Судья — Claude в сессии, как в прошлых циклах `/prompt-cycle`. Оценки:
   - **суть**: то же действие / бот лучше / бот хуже — против действия
     оператора;
   - **чек-лист регламента** «да / нет / неприменимо»: признание при стрессе,
     один шаг или один вопрос, «зачем» при просьбе данных, риск до действия,
     проверка результата, нет конвейерных фраз, нет выдуманных обещаний;
   - **«отправил бы почти как есть?»** — да / нет.

   По тому же чек-листу оцениваются ответы операторов. Это точка отсчёта «как
   пишут сейчас», а не эталон.
5. На 20 эталонах по регламенту: какой из двух вариантов ближе к эталону.
6. Владелец смотрит 10 пар.

### 7.3. Включение (каждый шаг — переключатель в `.env`)

1. `AGENT_VOICE_V2_ENABLED=true`: новый путь для 🔄 и первого сообщения тикета.
   Для первого сообщения это значит вернуть `AI_SUGGESTION_AUTO_ENABLED=true`,
   но в формате одного сообщения.
2. Через несколько рабочих дней без проблем — `AGENT_REPLY_DRAFTS_ENABLED=true`.
3. Откат — вернуть флаг в false и перезапустить бота.

### 7.4. Тихий замер

- `NIGHTLY_RECONCILE_ENABLED=true` включает только замер. Сводка по-прежнему
  выключена флагом `PERSONAL_DIGESTS_ENABLED=false`.
- Пополнение базы знаний после сверки (`process_pending_candidates`,
  `archive_unused_auto_rules`) выносится под новый флаг
  `RECONCILE_KB_DISTILL_ENABLED`, по умолчанию false. Это повторяет решение
  тихого режима: база сама не пополняется.
- Изменения судьи сверки (`agent/reconcile.py`):
  - новая категория `bot_better`;
  - фраза «объём и вежливость значения не имеют» убирается;
  - добавляется чек-лист регламента по черновику (оценивается сам черновик,
    без сравнения с оператором);
  - правило: выдуманное обещание или «ждите инженера» — это `bot_escalated`, а
    не `context_gap`;
  - результат чек-листа пишется в `judge_detail`.

## 10. Тесты

- **lint:** на каждое правило положительный пример, отрицательный и ложное
  срабатывание. Реальные примеры: #953, #1090, #1116, #1162, пароль в Памятке.
- **Запрос к поиску:** последнее сообщение «+7 913 …» или «Хорошо» не попадает в
  запрос, первое содержательное попадает.
- **История:** макрос «передано профильному специалисту, ожидайте звонка»
  вырезан, содержательная реплика оператора осталась.
- **Бюджет промпта:** худший случай ≤ 11 500 символов.
- **`stress`:** срабатывает на «опять…», «очередь», «где ваш сотрудник», не
  срабатывает на обычный вопрос.
- **Доставка:**
  - правка сообщения с черновиком;
  - NO_ACTION ничего не дописывает;
  - при переполнении 4096 символов текст обрезается;
  - клавиатура прошлого сообщения снимается.
- **Флаги:** при `AGENT_VOICE_V2_ENABLED=false` существующие тесты агента
  проходят без изменений.
- Весь набор: `python -m pytest tests/ -q` зелёный. Сейчас в нём 901 тест.
