# Навигация бота кнопками, без запоминания команд

Дата: 2026-10-12. Статус: дизайн согласован с владельцем, ждёт просмотра спеки.

## 1. Цель

Ни Игорю, ни Максиму с Юрием не нужно помнить ни одной команды. Любое действие бота
доступно кнопкой: в личке с ботом, в группе инженера и в топике тикета.

Команды не удаляются. Кто привык набирать `/send текст` или `/vacation 3d`, продолжает так делать.

Признак готовности: каждое действие из `DM_COMMANDS`, `GROUP_COMMANDS` и `HIDDEN_COMMANDS`
(bot/command_menu.py) доступно кнопкой, включая варианты с аргументами. Исключение — ввод
произвольной даты (см. «Не делаем»).

## 2. Что уже есть

- `/menu` и `/help` открывают inline-хаб (bot/command_menu.py, `cb_menu` в bot/handlers/commands.py).
  Хаб умеет только действия без аргументов. Остальное перечислено на экране «Команды с аргументами».
- `/start` удалён в редизайне 2026-05-19 (docs/superpowers/plans/2026-05-19-command-ui-redesign.md).
  Но новый пользователь, открыв личку с ботом, видит кнопку START, а по ней ничего не происходит.
  С появлением Максима и Юрия это стало реальной проблемой, поэтому `/start` возвращается
  как вход в хаб. В видимые списки команд он не попадает.
- В топике тикета обычный текст инженера в HDE не уходит. Отправка только через `/send`, `/note`;
  удаление через `/delete` ответом на сообщение; автополя через `/autofill`.
- Правка сообщения в Telegram синхронизируется в HDE (`on_edited_message`), если для этого
  `telegram_message_id` есть запись в `sent_messages`.

## 3. Решения владельца

| Вопрос | Решение |
|---|---|
| Где делать | Везде: меню и топики. Два этапа: сначала меню, потом топики |
| Как отвечать из топика | Сначала пишешь, потом жмёшь кнопку «Клиенту / Комментарий / ✖️» под своим сообщением |
| Кому служебные кнопки (Тишина, Синхрон, отчёты, AI-обслуживание, часы) | Всем троим, одно меню на всех. Известный риск: «Тишина» общая на весь бот, любой из троих выключит уведомления всем |
| Удаление из HDE кнопкой | С подтверждением «Точно?» |

## 4. Этап 1 — меню

### 4.1 Вход

- `/start` и `/menu`/`/help` показывают хаб.
- В личке постоянная reply-кнопка **☰ Меню** под полем ввода (`ReplyKeyboardMarkup`, `is_persistent=True`,
  `resize_keyboard=True`). Её ставит ответ на `/start` и `/menu` в личном чате. Нажатие присылает текст
  `☰ Меню`, его ловит хендлер `F.text == "☰ Меню"` и показывает хаб. В группах reply-клавиатуру не ставим:
  она висела бы во всех топиках.
- Видимые списки команд: `DM_COMMANDS = [menu]`, `GROUP_COMMANDS = [menu]`. Все прежние команды
  остаются зарегистрированными хендлерами и работают при наборе.

### 4.2 Хаб

```
[📊 Статус]        [🔄 Синхрон]
[💤 Тишина ▸]      [📈 Отчёты ▸]
[🤖 AI ▸]          [⏳ Часы «Беру» ▸]
[❓ Как отвечать из топика]
```

Навигация по подменю редактирует то же сообщение (`edit_text`), как сейчас. Действия отвечают
новым сообщением, как сейчас.

### 4.3 Подменю

**💤 Тишина ▸.** Заголовок показывает состояние: «Тишина до 14.10 09:00 МСК» (из `work_schedule.vacation_until()`)
или «Тишина выключена».
```
[До след. раб. дня] [1 д] [3 д] [7 д]
[▶️ Снять тишину]          ← только если тишина включена
[⬅️ Назад]
```
«N д» = `now_utc + N дней`, ровно как `/vacation Nd`. «До след. раб. дня» = `next_work_start()`.
Логику расчёта `until` выносим из `cmd_vacation` в одну функцию, её вызывают и команда, и кнопки.

**📈 Отчёты ▸.**
```
[📈 Отчёт за вчера]
[📅 Другой день ▸]   → 7 последних рабочих дней до вчера включительно (по config.work_days), кнопка «пн 06.10»
[🗓 Неделя ▸]        → [Прошлая] [Позапрошлая] [3 недели назад]
[🌅 Утренняя сводка]
[⬅️ Назад]
```
«Другой день» вызывает тот же код, что `/report YYYY-MM-DD`. «Неделя» вызывает тот же код,
что `/weekly YYYY-MM-DD`, с датой воскресенья: последнее воскресенье ≤ сегодня, минус 7 и 14 дней.
Семантику аргумента `run_weekly_summary(today)` проверить при реализации и закрепить тестом.
Тело `cmd_report`/`cmd_weekly` выносим в функции `(target: Message, day: date | None)`, команды
и кнопки зовут их.

**🤖 AI ▸.**
```
[🧠 Саммари: вкл ✅]     ← подпись из настройки ai_summary_enabled, нажатие переключает и перерисовывает
[📚 База знаний] [📊 Статистика]     ← cmd_aimetrics / cmd_aiknowledge
[🛠 Обслуживание ▸]
[⬅️ Назад]
```
**🛠 Обслуживание ▸:** Импорт тикетов (`/aiimport` без аргументов, то есть 50 своих), Переиндексация,
Дозаполнить организации, Анализ паттернов, Оптимизация промпта, Откат промпта. Каждая сначала
показывает «Запустить «…»? [Да] [Отмена]», потом зовёт существующий хендлер с `callback.message`
(и `CommandObject`-заглушкой с `args=None`, где хендлер его требует). При реализации проверить,
что ни один из шести хендлеров не читает `message.from_user` для прав: у `callback.message`
автор — сам бот.

**⏳ Часы «Беру» ▸.** Сетка `1 · 1–2 · 2 · 3 · 4 · 6 · 8 · 24`, у выбранных ✅. Нажатие сразу
добавляет или убирает вариант в настройке `take_busy_hours` и перерисовывает сетку. Порядок
сохранения — по сетке. Нельзя убрать последний вариант и нельзя выбрать седьмой: ответ
`callback.answer("От 1 до 6 вариантов", show_alert=True)`. Валидация через существующий `parse_busy_options`.

**❓ Как отвечать из топика.** Короткая памятка про этап 2: написал → кнопка; 🗑 удаляет из HDE;
правка своего сообщения правит его в HDE; голосовое — заметка по звонку; 🪄 — автополя.
Последняя строка: «Команды /send, /note, /delete, /autofill тоже работают».

Экран «Команды с аргументами» (`ARGS_HELP_TEXT`, `menu:args`) удаляется.

### 4.4 Попутно

Кнопки «Статус» и «Синхрон» сейчас дублируют код `cmd_status`/`cmd_refresh`, и у кнопки
«Статус» нет блока метрик. Выносим `_status_text()` и `_run_refresh(target: Message)`,
их зовут и команды, и кнопки.

### 4.5 callback_data

Всё под префиксом `menu:` (лимит Telegram 64 байта соблюдается):

| Данные | Действие |
|---|---|
| `menu:root`, `menu:quiet`, `menu:reports`, `menu:ai`, `menu:maint`, `menu:hours`, `menu:howto`, `menu:days`, `menu:weeks` | экраны |
| `menu:vac:next`, `menu:vac:1`, `menu:vac:3`, `menu:vac:7`, `menu:workon` | тишина |
| `menu:report_yesterday`, `menu:rep:2026-10-06`, `menu:week:2026-10-05`, `menu:digest` | отчёты |
| `menu:aisummary`, `menu:aimetrics`, `menu:aiknowledge` | AI |
| `menu:ask:<cmd>`, `menu:run:<cmd>` | обслуживание: подтверждение и запуск; `<cmd>` из белого списка шести команд |
| `menu:hour:<opt>` | переключить вариант часов |

Неизвестные `menu:*` логируются, как сейчас.

## 5. Этап 2 — топики тикетов

### 5.1 Поток

1. Инженер пишет в топик тикета текст, фото, альбом, видео, файл (не аудио) или GIF.
2. Бот отвечает на это сообщение (`reply_to_message_id`):
   `Куда отправить?  [📤 Клиенту] [💬 Комментарий] [✖️]`
3. Нажатие:
   - **📤 Клиенту / 💬 Комментарий.** Клавиатура снимается сразу, чтобы не было повторного нажатия.
     Вызывается `send_public_reply` / `add_internal_note` с `message=callback.message`, `command_args=None`,
     `tg_message_id=<id исходного сообщения>`. `prepare_outbound_message` берёт содержимое из
     `message.reply_to_message`, то есть из исходного сообщения, включая альбом из кеша медиа.
     Вопрос превращается в «✅ Отправлено клиенту» / «✅ Комментарий сохранён» и кнопку `[🗑 Удалить из HDE]`.
   - **✖️.** Вопрос удаляется.
   - **Ошибка HDE или конфигурации** (публичные ответы выключены, тикет не разрешён и т. п.):
     вопрос показывает текст ошибки (`format_operator_exception`) и прежние кнопки.
4. **🗑 Удалить из HDE** → «Удалить из HDE? Клиент мог уже прочитать. [Да, удалить] [Нет]».
   «Да» вызывает `delete_operator_message(telegram_message_id=<id исходного>)`, итог «🗑 Удалено из HDE».
   «Нет» возвращает `[🗑 Удалить из HDE]`.
5. Правка исходного сообщения в Telegram правит его в HDE: `tg_message_id` — id исходного сообщения,
   `on_edited_message` его найдёт. Нового кода для этого не нужно.

Состояние нигде не хранится. Исходное сообщение приходит в `callback.message.reply_to_message`.
Если инженер успел удалить исходное сообщение, `reply_to_message` пустой. Тогда бот отвечает
«Исходное сообщение удалено, отправлять нечего», а вопрос удаляет.

### 5.2 Когда вопрос не задаётся

- автор не инженер (`config.is_operator_allowed`) или бот;
- сообщение не в топике, или топик не привязан к активному тикету (`get_operator_topic_context` бросил `OperatorReplyError`); сюда входит General;
- команда (текст начинается с `/`);
- голосовое (`F.voice`): остаётся заметкой по звонку;
- аудио или файл-запись звонка (`F.audio`, либо `extract_audio_meta(message)` не `None`): остаётся транскрипцией;
- служебные сообщения топика (создание, переименование): фильтр по типам контента;
- инженер нажал «✏️ Исправить» у черновика: `capture_correction` в `ai_feedback_router` стоит раньше и забирает текст первым (так и остаётся).

**Альбом.** На альбом один вопрос: хендлер помнит последние `media_group_id` (ограниченное множество
в памяти, например последние 200) и отвечает только на первое сообщение группы. Все сообщения альбома
кешируются `cache_incoming_topic_media`, как сейчас. При рестарте посреди альбома максимум появится
второй вопрос, это безвредно.

### 5.3 Автополя

`suggest_button_kb()` получает вторую кнопку: `[💡 Предложить ответ] [🪄 Автополя]`
(`callback_data="tp:autofill"`). Тело `cmd_autofill` выносится в функцию
`run_autofill(bot, chat_id, topic_id, tg_user_id) -> str`, её зовут команда и кнопка.
При выключенном ИИ — ответ `operators.AI_OFF_NOTE`, как у команды.

### 5.4 Порядок роутеров

Новый `bot/handlers/topic_actions.py` со своим `router`. Он подключается в `commands.router`
**перед** `_media_router`: иначе catch-all `cache_topic_media` и `handle_topic_call_recording`
(ловит `F.document`) перехватят сообщения раньше. Хендлер вопроса сам вызывает
`cache_incoming_topic_media(message)`, чтобы кеш медиа для альбомов и `/send` ответом не потерялся.

### 5.5 callback_data

| Данные | Действие |
|---|---|
| `tp:client`, `tp:note`, `tp:cancel` | вопрос «Куда отправить?»; исходное сообщение берётся из `reply_to_message` |
| `tp:del:<orig_id>`, `tp:delyes:<orig_id>`, `tp:delno:<orig_id>` | удаление из HDE с подтверждением |
| `tp:autofill` | автополя |

Права проверяет `get_operator_topic_context(telegram_user_id=callback.from_user.id, ...)`.
HDE-авторизация — нажавшего (`hde_auth_for_user`), как у команд.

## 7. Выкатка и проверка вживую

Каждый этап отдельным коммитом в `main`. Затем на config1: pull и `systemctl restart hde-bot`.
Списки команд перерегистрирует `set_my_commands` при старте.

- Этап 1: в личке `/start` → хаб и кнопка ☰; пройти все подменю; «Тишина» не нажимать.
  Часы переключить и вернуть как было.
- Этап 2: в топике своего тикета написать тестовую фразу → «💬 Комментарий» → проверить
  внутренний комментарий в HDE (клиент его не видит) → «🗑» → «Да» → комментарий исчез.
  Публичную отправку клиенту вживую не проверяем без отдельного согласия.
- Журнал: /opt/hde-bot/logs/bot.log (не journalctl).

## 8. Не делаем

- Календарь для выбора произвольной даты тишины или отчёта. Набранные `/vacation 2026-10-20`
  и `/report 2026-09-01` остаются.
- Разные меню для разных людей (владелец выбрал одно на всех).
- Склейку нескольких сообщений в один ответ клиенту.
- Автоудаление неотвеченных вопросов «Куда отправить?».
- Тишину отдельно для каждого инженера (это отдельная задача, если понадобится).

## 9. Риски

- **Шум в топике.** Бот отвечает на каждое сообщение инженера. Смягчение: ✖️ удаляет вопрос,
  после отправки вопрос превращается в однострочный итог. Если шум мешает, следующий шаг — удалять
  итог через N минут (не в этой задаче).
- **Общая тишина на виду.** Любой из троих выключит уведомления всем. Принято владельцем.
- **Хендлеры обслуживания вызываются с сообщением бота.** Если какой-то читает `message.from_user`,
  он сломается. Проверяется при реализации, см. 4.3.
