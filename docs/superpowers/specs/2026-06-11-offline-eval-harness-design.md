# Офлайн eval-харнесс, LLM-judge и человеческий стиль ответов

Дата: 2026-06-11
Статус: дизайн утверждён, ожидает ревью спеки

## Проблема

Промт суммарок (`_FORMAT_INSTRUCTIONS`, активная версия в таблице `prompt_versions`)
улучшается вслепую: ночной `/aioptimize` мутирует его слабыми моделями
(llama-3.1-8b / gemma2-9b via Groq) и оценивает грубой similarity-метрикой на
~20 сэмплах без holdout. Осмысленно править промт и проверять результат до
деплоя негде. Дополнительно: ответы бота для клиентов звучат «по-ИИшному» —
заметна разница между живым оператором и ботом.

## Решение (обзор)

Два контура оптимизации над общими артефактами (`prompt_versions`,
`optimization_samples` в SQLite):

1. **Локальный контур** — стянуть базу с VPS, офлайн eval-харнесс: replay
   реальных тикетов кандидатом промта, двухслойный скоринг (существующий
   evaluator + новый LLM-judge), сравнение с активным промтом до деплоя.
2. **Ночной контур** — апгрейд `/aioptimize`: мутации через Gemini 2.5 Flash,
   оценка финалистов judge-ом на holdout.

Плюс «человеческий стиль»: русский анти-ИИ стайлгайд (дистилляция skill-ов
stop-slop и humanizer), профиль голоса из реальных ответов оператора,
критерий `sounds_human` в judge.

API не меняются: Gemini 2.5 Flash (тот же `GEMINI_API_KEY`), Groq остаётся
fallback. Embeddings локальные (multilingual-e5-large), не трогаем.

## Компоненты

### 1. Перенос базы — `scripts/pull_kb.sh`

Одна команда: `scp` файла `hde_bot.db` с config1 в `./data/hde_bot_vps.db`.
База самодостаточна: `optimization_samples` (датасет: history, ai_answer,
op_answer, outcome, confidence), `prompt_versions`, `knowledge_items`
(включая embeddings BLOB — пересчёт не нужен).

### 2. Eval-харнесс — `scripts/eval_prompt.py`

CLI поверх локальной копии базы:

- Вход: `--prompt file.md` или `--version N`; без аргументов — active vs
  последний candidate. `--db` — путь к базе (default `./data/hde_bot_vps.db`).
- Сэмплы делятся на train/holdout 80/20 детерминированно (фикс. seed по
  `sample_id`).
- Для каждого сэмпла генерируется ответ кандидатом через Gemini
  (существующий `LLM_SEMAPHORE(3)`, при 429 — backoff).
- Кеш ответов: локальная таблица `eval_cache` с ключом
  `(prompt_hash, sample_id)` — прерванный прогон резюмится, повторные
  прогоны бесплатны.
- Скоринг: `0.5 * evaluator.combined_score + 0.5 * judge.overall/10`
  (коэффициенты — константы в коде).
- Вывод: таблица per-outcome (sent/accepted/corrected/rejected), дельта
  против active, топ худших регрессий с текстами (что именно ухудшилось).
- Если сэмплов < 30 — явное предупреждение о ненадёжности оценки.

### 3. LLM-judge — `bot/optimizer/judge.py`

Общий модуль для харнесса и ночного оптимизатора:

- Вход: history тикета + ответ кандидата + реальный ответ оператора.
- Gemini 2.5 Flash, temperature=0, structured output (responseSchema):
  `{diagnosis_correct, equipment_named, format_ok, length_ok,
  sounds_human, overall (0-10), reason}`.
- `sounds_human`: проверка по анти-ИИ стайлгайду + сравнение тона с
  примерами голоса оператора.
- Экономия квоты: в ночном контуре judge гоняется только для топ-2
  финалистов на holdout, не на каждой мутации.

### 4. Апгрейд ночного оптимизатора

- `bot/optimizer/mutations.py` + `llm_router.py`: приоритет мутаций —
  Gemini 2.5 Flash, Groq-модели как fallback (сейчас наоборот).
- `bot/optimizer/agent.py`: финалисты оцениваются judge-ом на holdout;
  порог apply (3%) считается по holdout-скору — лечит переобучение.

### 5. Русский анти-ИИ стайлгайд — `bot/prompts/style_guide_ru.md`

Дистилляция stop-slop (github.com/hardikpandya/stop-slop) и humanizer
(github.com/blader/humanizer), адаптированная под русский и короткие
ответы поддержки кассового оборудования:

- Запрет чат-артефактов: «Надеюсь, это поможет», «Отличный вопрос!»,
  «Дайте знать», generic-концовки.
- Пассив → актор: «перезагрузите кассу», не «должна быть произведена
  перезагрузка».
- Без ИИ-канцелярита: «является», «данный», «осуществить», «в рамках»,
  «важно отметить», «на сегодняшний день».
- Без структур «не просто X, но и Y», навязчивых троек, стаккато-драмы,
  signposting («Давайте разберёмся»).
- Конкретика (модель, кнопка, срок) вместо обобщений; «вы» вместо
  «пользователи»; hedging-стопки («возможно, вероятно») — резать.
- НЕ переносим английские правила, ломающие русский: запрет тире
  (в русском тире грамматически обязательно), Title Case, copula
  avoidance (наоборот — флагаем «является»).

Свод вшивается в текст промта (через `prompt_versions` — деплой без правки
кода), применяется в первую очередь к полю «Клиенту». Двухпроходный
самоаудит из humanizer в рантайм не берём: удваивает латентность и квоту.

### 6. Профиль голоса — `scripts/build_voice_profile.py`

- Источник: `optimization_samples.op_answer` с outcome='corrected' —
  эти тексты владелец набирал сам через кнопку ✏️, то есть это и есть
  «мои ответы»; отдельный фильтр по оператору не нужен. Outcome 'sent'
  не берём: там может быть ИИ-текст, отправленный без правок.
  При нехватке примеров — добор из истории тикетов HDE.
- Скрипт отбирает характерные ответы → 5-8 живых примеров + краткое
  описание манеры (длина фраз, приветствия, лексика).
- Результат — `bot/prompts/voice_profile.json`, подключается в промт как
  few-shot (вместо/вдобавок к статичному `few_shot_examples.json`).

## Поток данных

```
VPS hde_bot.db ──scp──> data/hde_bot_vps.db
                            │
        build_voice_profile.py ──> voice_profile.json ─┐
                            │                          │
   правка промта (вручную/Claude, style_guide_ru.md) ──┤
                            │                          ▼
        eval_prompt.py: replay сэмплов ──> Gemini ──> ответы кандидата
                            │
        скоринг: evaluator.combined_score + judge (Gemini, T=0)
                            │
        отчёт: дельта vs active, худшие регрессии
                            │ (если лучше)
        INSERT в prompt_versions (candidate) ──> apply кнопкой в боте
```

Ночной контур: тот же judge и holdout, мутации Gemini.

## Обработка ошибок

- Gemini 429/недоступен: backoff через существующий semaphore; харнесс
  резюмится с `eval_cache`; ночной контур — fallback Groq (как сейчас).
- Битый JSON от judge: повтор 1 раз, затем сэмпл помечается unscored и
  исключается из среднего (логируется).
- Мало данных (< 30 сэмплов): предупреждение, judge-скор помечается
  ненадёжным; apply в ночном контуре блокируется (текущий минимум
  10 примеров сохраняется как нижняя граница).

## Тестирование

- Unit: парсинг ответа judge, детерминизм train/holdout split,
  eval_cache hit/miss, формула итогового скора, фильтр voice profile
  по ID оператора.
- Gemini-вызовы мокаются; интеграционный прогон — вручную на стянутой
  базе с реальным ключом.

## Вне скоупа (backlog)

- Динамический few-shot из KB по тематике/компании.
- KB-гигиена: дедуп, протухание bad-записей, перевзвешивание RRF.
- Structured output для основного промта суммарок.
- Context caching Gemini для системного промта.

## Критерии успеха

1. `pull_kb.sh` + `eval_prompt.py` дают воспроизводимый скор активного
   промта на реальных данных за один запуск.
2. Кандидат промта со стайлгайдом и профилем голоса обгоняет текущий
   active по итоговому скору на holdout.
3. Ночной `/aioptimize` применяет промты только по holdout-скору.
4. Судья стабильно (повторный прогон, T=0) различает «ИИ-стиль» и
   реальные ответы оператора по критерию `sounds_human`.
